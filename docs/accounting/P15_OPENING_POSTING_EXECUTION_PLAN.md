## 3 · التشغيل التجريبي

**الغرض:** إثبات المسار الكامل — التحقق والتوازن واختيار الفترة وربط الحسابات —
**بلا ترحيل**.

```
1. قراءة البيان والتحقق من بصمته
2. تحويل الرموز الثلاثة عشر إلى معرّفات الحسابات · أي رمز غير موجود ⇒ توقّف
3. POST /api/accounting/entries    ← ينشئ مسوّدة، لا يرحّل
     المحرّك يُشغّل هنا: prepareLines · assertBalanced ·
     assertOpeningBalanceAccounts · selectPeriod · resolveBackdating
4. GET  /api/accounting/entries/:id  ← فحص: الفترة 0 · الإجماليات · 13 سطراً
5. DELETE المسوّدة                  ← مسموح للمسوّدات فقط
6. تأكيد journal_entries = 0
```

**لماذا آمن:** المسوّدة **لا تستهلك رقماً رسمياً** — الترقيم يُسنَد عند الترحيل
وحده، فحذفها لا يُحدث فجوة. ولا أثر لها في أي ميزان: `trialBalance` تقرأ
`status IN ('posted','reversed')` فقط.

**الفحوص التي يُثبتها التشغيل التجريبي فعلياً:**

| الفحص | من يفرضه |
|---|---|
| التوازن | `assertBalanced` + `chk_je_posted_balanced` |
| كل سطر مدين أو دائن | `chk_jl_one_side` |
| لا حساب نتيجة | `assertOpeningBalanceAccounts` |
| الفترة 0 لا يناير | `selectPeriod('opening_balance', …)` |
| حسابات نشطة وقابلة للترحيل | `prepareLines` |
| كل السطور باليورو بسعر 1 | `chk_jl_eur_rate_is_one` |

## 5 · منع الازدواج — مُثبَت بالمحرّك

```sql
CREATE UNIQUE INDEX uq_je_accounting_event ON journal_entries
  (legal_entity_id, accounting_event_type, source_type, source_id)
  WHERE source_id IS NOT NULL AND status <> 'void';
```

البيان يحمل `source_type = 'opening'` و`source_id` ثابتاً معلوماً. فأي محاولة
لترحيل قيد افتتاحي ثانٍ لنفس الكيان **ترتطم بفهرس فريد في قاعدة البيانات** وتُرفض

**مُثبَت عملياً** (فحص E1 من الـ87): نفس المستند + نفس نوع الحدث مرتين ⇒ مرفوض.

⚠️ ولأن `source_id` ثابت في البيان، **إعادة تشغيل السكربت بالخطأ لا تُنتج قيداً
ثانياً** — تُنتج خطأ صريحاً.

## 6 · إثبات الفترة 0

```
selectPeriod('opening_balance', [P0, P1])  →  period_no = 0
selectPeriod('manual',          [P0, P1])  →  period_no = 1
```

الفترة 0 `[2026-01-01 → 2026-01-01]` ويناير `[2026-01-01 → 2026-01-31]` يتقاطعان
في يوم واحد — **ونوع الحدث هو ما يفصل، لا التاريخ**. مُثبَت باختبارين مستقلين
(40 و41) وبخمسة أنواع أحداث.

`assertDateInPeriod` تتحقق أن `2026-01-01` داخل حدود الفترة 0، و`trg_je_period_guard`
يرفض الترحيل لو كانت الفترة مُقفلة.

## 12 · خطة العكس والتراجع

### قبل الترحيل
لا شيء يُتراجَع عنه — التشغيل التجريبي يحذف مسوّدته، والحالة تعود صفراً.

### بعد الترحيل — القيد لا يُعدَّل ولا يُحذف

```
trg_je_immutable            يقارن الصف كاملاً كـjsonb
trg_jl_immutable            الأسطر لا تُمسّ
trg_je_balanced_deferred    التوازن يُفحص عند COMMIT
REVOKE + RLS                لا التفاف من الـData API
```

### مساران للتصحيح — ولا ثالث

**١ · العكس** — خطأ جوهري يستدعي إلغاء الافتتاح كله:
`POST /api/accounting/entries/:id/reverse` ينشئ قيداً مضاداً بالسعر الأصلي ويربط
الطرفين، ثم يُرحَّل بيان مصحَّح.

**٢ · قيد تسوية افتتاح** — تصحيح جزئي عند ورود مستند أو تعديل مدقّق:
حدث `adjustment` يحمل الفرق ومبرّره ومرجع القيد الأصلي.

### ⚠️ خاصية يجب أن تُعرف قبل الاعتماد

**العكس وقيد التسوية يقعان في فترة تشغيلية لا في الفترة 0** — `selectPeriod`
تستثني الفترة 0 لغير `opening_balance`. أثره:

```
الفترة 0        تبقى تعرض الافتتاح الأصلي كما رُحِّل — إلى الأبد
يناير فصاعداً    تعرض التصحيح وأثره
الأثر التراكمي   صحيح من تاريخ التصحيح
```

هذا **مقصود لا عَرَض**: سجلّ الافتتاح لا يُعاد كتابته، والخطأ وتصحيحه يبقيان
مقروءين معاً. لكنه يعني أن ميزان الفترة 0 وحدها سيظل يحمل الرقم الأصلي.
