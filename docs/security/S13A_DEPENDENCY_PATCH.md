## لماذا لم تكفِ الترقية

المحاولة الأولى كانت الحل الطبيعي: ترقية الحزمة الأب.

```
swagger 11.4.5  →  يثبّت js-yaml 4.3.0     النطاق المصاب 4.0.0 – 4.3.0
swagger 11.4.6  →  يثبّت js-yaml 5.2.1     النطاق المصاب 5.0.0 – 5.2.1
```

**استبدلت نسخة مصابة بأخرى.** التنبيه بقي — لا لخطأ في التثبيت، بل لأن استشارة
الأمان تغطّي خطّي الإصدار معاً، و`11.4.6` هو **آخر إصدار مستقر** فلا إصدار أب
يحلّها.

و`@nestjs/swagger` يثبّت `js-yaml` **بنسخة محدَّدة لا بنطاق**، فـ`npm update js-yaml`
وحده لا يؤثّر فيه.

## الإصلاح المطبَّق

```json
"overrides": {
  "@nestjs/swagger": {
    "js-yaml": "^5.2.3"
  }
}
```

**تجاوز مُوجَّه لا شامل** — يستهدف نسخة `swagger` وحدها. نسخة `js-yaml 4.3.0`
الموجودة في شجرة التطوير (`@eslint/eslintrc` · `@nestjs/cli`) لم تُمسّ.

**لماذا تجاوز:** لأن الحزمة الأب لا تملك إصداراً يحلّها. هذا هو المسار الوحيد
المتبقّي بعد استنفاد الترقية.

```
package.json  "@nestjs/swagger": "^11.4.5"     ← لم يتغيّر
المثبَّت       11.4.6
المفروض       node_modules/@nestjs/swagger/node_modules/js-yaml  5.2.3
شجرة التطوير  node_modules/js-yaml  4.3.0                        ← لم تُمسّ
```

لم يُستخدم `--force` ولم يُتجاوَز أي تعارض تبعيات.

## اكتشاف جوهري — الحزمة غير مستخدمة أصلاً

```
SwaggerModule       صفر استيراد في src/ و test/
DocumentBuilder     صفر
@ApiProperty · @ApiTags · @ApiOperation   صفر
nest-cli.json       بلا إعداد swagger
```

**`@nestjs/swagger` تبعية ميتة.** لا وثائق API مُولَّدة ولا نقطة `/api-docs`.
وهذا يفسّر لماذا لم يُنتج التجاوز أي انحدار: لا شيفرة تشغيل تمرّ بها.

**التوصية:** حذف الحزمة يُغني عن التجاوز ويحذف `swagger-ui-dist` وشجرتها كاملة.
**لم يُنفَّذ** — خارج تصريح "ترقيع"، ويحتاج إذناً مستقلاً.
