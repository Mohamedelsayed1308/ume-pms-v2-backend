# مرتّبات أطقم السفن — دليل التشغيل

الشاشة: `/dashboard/fleet-crew-salaries`
الواجهة البرمجيّة: `api/crew-salaries`
الوحدة: `src/modules/crew-salaries`

## أوّل تشغيل: بيئة منفصلة قبل الإنتاج

لا يُجرَّب أوّل مرّةٍ على الإنتاج. يُنشأ مشروع Supabase منفصل (أو فرعٌ منه)، وتُطبَّق عليه
الهجرة، ويُقلع عليه باكٌ وفرونتٌ منفصلان:

```
NEXT_PUBLIC_API_URL=<عنوان باك البيئة المنفصلة>
```

ثمّ تُجرى دورة أغسطس كاملة، ثمّ يُفتح باب النشر أدناه.

## بوّابة النشر (كلّ بندٍ يُتحقَّق منه ويُسجَّل)

1. نسخةٌ احتياطيّة من القاعدة.
2. **القيد الفريد على `exchange_rates.month`**: كتابة السعر تستعمل `ON CONFLICT (month)`.

```
SELECT conname FROM pg_constraint WHERE conrelid = 'exchange_rates'::regclass AND contype = 'u';
```

3. تشغيل الهجرة، ثمّ رسالة «RLS مفعّلة، والوصول المباشر مسحوب»:

```
node scripts/run-migration.js docs/crew-salaries-up.sql
```

4. **أمان الجداول على Supabase نفسه** (لا تكفي PostgreSQL المحلّيّة):
   - `relrowsecurity = true` للجداول العشرة.
   - لا صلاحيّات لـ `anon` ولا `authenticated` ولا `service_role`:

```
SELECT grantee, table_name, privilege_type FROM information_schema.role_table_grants
WHERE table_name LIKE 'crew_salary_%' AND grantee IN ('anon','authenticated','service_role');
```

   - طلبٌ من Data API بمفتاح `anon` على أيّ جدول مرتّبات يُرفض.
   - دور اتّصال الباك (DATABASE_URL) هو مالك الجداول — فيعمل رغم RLS.
5. متغيّر المعتمد على Railway:

```
CREW_SALARY_APPROVER_USER_ID=8712bd6f-1880-4fd7-9a7d-8e9976e88eb1
```

أكّد المالك في ٢٧ سبتمبر ٢٠٢٦ أنّ هذا حسابه (`mohamed@ume.com`) وأنّه المعتمد الوحيد.

6. نشر الباك، ثمّ `GET /api/health`، ثمّ أنّ `/api/crew-salaries/permissions` يردّ 401 بلا دخول.
7. نشر الفرونت.
8. منح الشاشة لمن يلزم. وتعديل أسعار الشركة يبقى لمن يملك شاشة التقارير.
9. سلامة البيانات: استيراد رسالة الشهر وتصديري CFM، ومطابقة الإجماليّات بأرقام المالك المعروفة.

التراجع: `docs/crew-salaries-down.sql`. والبوّابة ترفض الحذف إن وُجد أيّ صفّ، إلّا بإعدادٍ على مستوى الجلسة قبل الملفّ:

```
PGOPTIONS='-c crew_salary.force_drop=yes' node scripts/run-migration.js docs/crew-salaries-down.sql
```

## صاحب صلاحية الاعتماد

- غياب المتغيّر أو فساده = **لا معتمد**: كلّ اعتمادٍ مرفوض.
- لا يُمنح لكلّ أدمن، ولا يُعدَّل من الواجهة.
- الاعتماد يشمل إصدارات المرتّبات وحسابات الصرف وتفويضات المستفيد.

## أسعار الصرف

- من جدول `exchange_rates` القائم، لشهر الدورة نفسه فقط. لا صفّ `default` ولا قيمةٌ مضمَّنة.
- الإدخال «١ EUR = X USD» بستّ منازل على الأكثر، ويُخزَّن مقلوباً (وحداتٌ لكلّ دولار) بخمسة عشر رقماً معنويّاً، ويُستردّ بستّ منازل مطابقاً للمدخَل حرفيّاً. التحويل: المبلغ × q(من) ÷ q(إلى) ثمّ تقريبٌ واحد.
- الكتابة ذرّيّة لعملةٍ واحدة (`ExchangeRatesService.setOne`)، ولمن يملك شاشة التقارير.
- **حدّ باقٍ:** بطاقة الأسعار في شاشة التقارير تستبدل الشهر كلّه عند حفظها — كما كانت. تزامنها مع إدخال المرتّبات يمكن أن يضيع أحدهما؛ والإصدار المعتمد محميّ بلقطته.

## ملفّات PDF

- وثائق الهويّة والعقود (بالاسم) لا يُستخرج نصّها.
- الاستخراج في عمليّةٍ فرعيّة معزولة بمهلةٍ وحدٍّ للمخرَج (`pdf-parse`).
- المستند الماليّ المعروف اليوم: كشف توزيع اللاشينج — مرجعٌ يُظهر التعارض مع الرسالة ولا يستبدلها.

## الاختبارات

```

npm run test:pg
```

- العنقود المؤقّت في مجلّد النظام المؤقّت، والتهيئة الأولى ~٩٠ ثانية، والقواعد UTF8 صراحةً.
- التنظيف بعد الاختبار يُنهي عمليّات عنقود الاختبار وحده.

عيّنة حقيقيّة (لا تدخل Git أبداً):

```

CREW_SAMPLE_DIR=<المجلّد نفسه> npm run test:pg -- crew-salaries.sample
```

## حدود هذه المرحلة

- لا إرسال تحويلات، ولا تأكيد سداد، ولا قيود محاسبيّة. «صُدِّر» ليست «سُدِّد».
- كشف الصرف Excel عامّ، لا يُسمّى «جاهزاً للبنك». قالب كلّ بنك يُضاف لاحقاً.
- الرقم القوميّ لا يُقرأ ولا يُخزَّن: لا قالب بنكٍ معتمد يطلبه بعد.
- رسائل الخادم (الأخطاء وتفاصيل القضايا) بالعربيّة؛ الواجهة نفسها بالعربيّة والإنجليزيّة.
- ملفّات الرسالة تُخزَّن داخل القاعدة (`bytea`)، نحو ١٤MB لكلّ مركبٍ شهريّاً.
