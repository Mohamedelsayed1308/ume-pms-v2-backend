# سياسة تغيير المخطط — UME PMS v2

## لماذا وُجدت هذه الوثيقة

أثناء إصدار R3A فقدت قاعدة الإنتاج بيانات فعلياً.

التسلسل:

1. هجرة صريحة أضافت ثلاثة أعمدة تحكّم مالي إلى `invoices` ووسمت 128 فاتورة تاريخية.
2. نشر تالٍ للباك فشل في الإقلاع لسبب غير متعلّق بالمخطط.
3. أُرجع الكود (`git revert`) لإعادة الخدمة — وهو الإجراء الصحيح.
4. النسخة المُرجَعة لا تعرف الأعمدة الثلاثة، و`synchronize: true` كان مفعَّلاً.
5. **TypeORM أسقط الأعمدة الثلاثة ومعها التوسيم بالكامل — صامتاً، بلا خطأ ولا تحذير.**

لم يكن ذلك خللاً في TypeORM بل سلوكه المعلن: **الكيان هو مصدر الحقيقة، وكل ما لا يجده في البيانات الوصفية يُحذف** — أعمدة وقيود CHECK ومفاتيح خارجية وفهارس، والمطابقة **بالاسم فقط**.

النتيجة العملية:

> مع `synchronize: true`، إرجاع الكود — وهو أسلم إجراء عند عطل — يصير **عملية مدمِّرة للبيانات**.

استُرجع التوسيم كاملاً لأن البيان كان مجمَّداً والهجرة متكرّرة الأمان. لكن الخطر بنيوي ولا يجوز الاعتماد على الحظ.

## القواعد

### 1. الإنتاج لا يعدّل مخططه تلقائياً

```
NODE_ENV = production            →  synchronize: false
NODE_ENV = development|dev|test  →  synchronize: true
غير معلَن / غير معروف            →  يُعامَل إنتاجاً  →  false
```

القرار في [`src/common/schema-policy.ts`](../src/common/schema-policy.ts). **fail-closed:** البيئة المجهولة إنتاج. لا fallback ضمني.

### 2. حاجز يمنع التسرّب

`assertNoAutoDdlInProduction` يُوقف الإقلاع فوراً لو صار `synchronize=true` في الإنتاج بأي طريق — تحرير خاطئ أو دمج أو إعداد بيئة. **التوقّف الصريح أرخص بكثير من فقدان بيانات صامت.**

### 3. كل تغيير مخطط في الإنتاج يمرّ بهجرة صريحة

لا استثناء. المرجع العملي: [`src/migrations/r3a-legacy-2026-08.ts`](../src/migrations/r3a-legacy-2026-08.ts).

الخصائص الواجبة في أي هجرة:

- **صريحة** — SQL مقروء قابل للمراجعة، لا اشتقاق من كيانات.
- **معامَلاتية** — Postgres يدعم DDL داخل معاملة؛ فشل أي بوابة يتراجع بالكامل.
- **متكرّرة الأمان** — `IF NOT EXISTS` · `ON CONFLICT DO NOTHING` · `EXCEPTION WHEN duplicate_object` · شروط تمنع إعادة التطبيق.
- **مُبوَّبة** — تتحقق من الحالة قبل الكتابة وترفض المتابعة عند أي انحراف.
- **قابلة للتراجع** — بلا اختراع بيانات.
- **مُتحقَّق منها بعدها** — بصمة مالية كاملة قبل/بعد، لا مجرد عدّ صفوف.

### 4. أسماء القيود تُثبَّت وتُعلَن في الكيان

TypeORM يوفّق CHECK والمفاتيح الخارجية والفهارس **بالاسم**، ويُسقِط ما لا يجده. لذلك:

- اسم كل قيد ثابت مُصدَّر يشترك فيه SQL والكيان.
- الكيان يعلنه بـ`@Check(NAME, EXPR)` و`@JoinColumn({ foreignKeyConstraintName })`.
- إغفال ذلك يمحو ضمانة النزاهة صامتاً عند أول إقلاع.

### 5. الأعمدة الاتحادية تُعلن نوعها صراحةً

`@Column({ nullable: true }) x: string | null` **يُسقِط الخدمة**: `emitDecoratorMetadata` يختزل النوع الاتحادي إلى `Object` فيرفضه TypeORM عند بناء البيانات الوصفية — قبل الاتصال بالقاعدة أصلاً.

```ts
@Column({ type: 'varchar', length: 200, nullable: true })  x: string | null;   // صحيح
@Column({ length: 200, nullable: true })                   x: string | null;   // يسقط الإقلاع
```

يحرسه اختباران: [`entity-metadata.spec.ts`](../src/common/entity-metadata.spec.ts) و[`schema-policy.spec.ts`](../src/common/schema-policy.spec.ts).

### 6. النسخ الاحتياطي والتراجع

قبل أي هجرة تكتب على بيانات قائمة:

- لقطة قراءة فقط للصفوف المتأثرة، مُلتزَمة في المستودع.
- بيان عضوية مجمَّد ببصمة SHA-256 إن كانت المجموعة محدَّدة.
- SQL تراجع مكتوب ومراجَع **قبل** التنفيذ.

### 7. ترتيب النشر

```
1. الهجرة الصريحة  (تُنشئ المخطط والقيود)
2. التحقق          (بوابات + بصمة مالية قبل/بعد)
3. نشر الباك       (الكيانات تعرف المخطط الجديد بأسمائه)
4. نشر الفرونت
```

استثناء: لو أصدر الباك قيمة جديدة يستهلكها الفرونت (مستوى خطورة مثلاً)، **يُنشر الفرونت أولاً** — الريبوهان يُنشران مستقلين، والمستهلك يجب أن يقبل القيمة قبل أن تُرسَل.

### 8. الإرجاع بعد هذه السياسة

مع `synchronize: false` صار `git revert` آمناً: الكود يرجع، والمخطط لا يتأثر. تراجع المخطط — إن لزم — عملية منفصلة صريحة.

## نطاق ما لم يُنفَّذ

لم يُبنَ نظام هجرات كامل (`data-source.ts` + `migrations/` + CLI). ذلك تحوّل معماري أوسع يحتاج هجرة أساس لكل الكيانات القائمة، وخارج نطاق R3A.1.

المُنفَّذ: **إيقاف تعديل المخطط التلقائي في الإنتاج، وترسيخ الهجرة الصريحة قاعدةً.**

`migrationsRun: false` مضبوط صراحةً حتى لا تُشغَّل أي هجرة عند الإقلاع مستقبلاً — التنفيذ يبقى فعلاً مقصوداً.
